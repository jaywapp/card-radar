# 빌드 및 기능 검증 설계

KFTC 설정 예제는 String.fromEnvironment를 사용한다. 기존 로컬 설정이 없는 경우에만 예제를 복사하며 자격 증명 없는 상태는 명시적인 설정 오류로 처리한다. 기존 로컬·CI 상수 이름은 변경하지 않는다.

HTTP 오류에 응답 본문을 포함하지 않고, 잘못된 JSON과 필수 토큰 값은 안전한 형식 오류로 반환한다. 정상 카드명 순서·중복 및 누락 목록의 빈 값 계약은 유지한다. OAuth 콜백은 대기 중인 state가 존재하고 정확히 일치할 때만 처리한다. 빈 state의 검증 우회와 중복 콜백을 막는다.

기존 http 클라이언트의 테스트 대역 기능을 사용해 정상 요청·실패·잘못된 응답을 테스트한다. 설정 복사 후 flutter analyze, 전체 flutter test 및 가능한 APK 빌드를 실행한다. 화면의 레이아웃과 기능은 추가하거나 변경하지 않는다.

## API 21 호환성 결정

현재 `minSdk = 21`, pubspec.yaml, pubspec.lock, CI의 SDK 고정을 보존한다. 전역 `C:\flutter`를 교체하거나 Flutter 검증 플래그로 SDK 요구조건을 우회하지 않는다. 이번 후속은 검증 근거 문서만 변경한다.

대안 비교:

| 대안 | 판단 |
|---|---|
| 현재 SDK에서 minSdk를 24로 올리기 | 사용자 지원 OS 보존 조건에 위배되므로 제외 |
| 현재 SDK의 최소 SDK 검사 우회 | 실제 엔진·네이티브 라이브러리 호환성을 만들지 못하므로 제외 |
| Flutter 3.32.8만 고정 | 지도 플러그인 minSdk 23과 SDK 패키지 lock 차이가 남으므로 불충분 |
| 격리한 후보 SDK와 API 21 호환 지도 플러그인으로 별도 lock 재생성 | 별도 작업 후보. 정확한 지도 버전과 전체 호환 조합은 미확정 |

별도 작업의 완료 조건은 전역 설치를 변경하지 않는 SDK 격리, 버전별 Android 선언 및 API 차이 확인, 의도한 패키지만 변하는 lock diff 검토, 기존 30개 테스트 두 모드와 analyze 재통과, 실제 API 21 APK metadata 및 에뮬레이터/기기의 지도·권한·딥링크 동작 검증이다. 현재 API 24 산출물을 이 조건의 증거로 재사용하지 않는다.
